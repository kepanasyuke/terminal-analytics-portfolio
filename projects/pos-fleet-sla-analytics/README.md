# SLA и доступность парка терминалов

Расчёт соблюдения сервисных контрактов на парк POS-терминалов, киосков
самообслуживания и банкоматов: нормативы реакции и решения, фактические сроки,
неустойка по договору с лимитом и обоснованный план замены оборудования.

Данные синтетические. Период наблюдения, договорные нормативы и поток инцидентов
генерируются в `src/generate_fleet.py`; всё, что считается дальше, считается SQL-ом
из выгрузок — как в реальном сервисном контракте, где приходят только CSV.

## Результат на данных по умолчанию

90 устройств, 60 дней, 299 инцидентов:

| Показатель | Значение |
| --- | ---: |
| Инцидентов / критичных P1 | 299 / 31 |
| Нарушений SLA | 61 (20,4 %) |
| Доступность парка | 93,16 % |
| MTTR | 10,1 ч |
| Средняя реакция | 2,03 ч |
| Неустойка к выставлению | 1 205 950 ₽ (без лимитов 11 049 670 ₽) |
| Устройств с высоким приоритетом замены | 11 |

Доступность 93 % — сознательно «проблемный» парк: в него заложены хронические
устройства, из-за которых и появляется план замены. На здоровом парке показатель
выходит за 97 %.

## Что считается

- **Доступность** устройства с схлопыванием пересекающихся инцидентов и обрезкой
  открытых инцидентов по концу периода.
- **Нарушения SLA** раздельно по реакции (25 % от норматива решения) и по решению.
- **Неустойка** = месячная плата × ставка × полные часы просрочки, с лимитом
  на уровне «договор × месяц».
- **MTTR** только по закрытым инцидентам.
- **План замены** по совокупности признаков: доступность, критичные инциденты, возраст.

Методика с формулами и обоснованием — `docs/methodology.md`.

## Быстрый старт

Python 3.10+ (проверено на 3.14), SQLite 3.39+, внешних пакетов нет.

```powershell
python src/generate_fleet.py
python src/pipeline.py
python src/report.py
```

Результат: `reports/dashboard.html`, `reports/summary.md`, витрины в `data/processed/`.
Тесты:

```powershell
python -m unittest discover -s tests -v
```

## Структура

```
src/generate_fleet.py  генерация парка, договоров и инцидентов
src/pipeline.py        загрузка в SQLite, SQL-расчёты, выгрузка витрин
src/report.py          HTML-дашборд и markdown-резюме
sql/01_schema.sql      схема: договоры, устройства, инциденты, период наблюдения
sql/02_marts.sql       расчёт SLA, доступности, неустойки, плана замены
tests/test_sla.py      независимый пересчёт нарушений SLA и проверка формул штрафа
docs/methodology.md    методика: формулы, спорные места, почему так
```

## Принятые решения

- **Период наблюдения — отдельная сущность.** Если считать его по диапазону инцидентов,
  устройства без отказов выпадают из знаменателя и доступность завышается.
- **Просрочка реакции не штрафуется деньгами.** Иначе один и тот же час учитывается
  дважды; для денег важен только срок решения.
- **Лимит неустойки — на договор и месяц.** Расчёт по инциденту даёт штраф,
  превышающий месячную плату в разы.
- **Суммы в копейках.** Ни одной операции с плавающей точкой на деньгах.
- **Пересекающиеся инциденты схлопываются.** Иначе простой суммируется дважды
  и доступность уходит в минус.

## Ограничения

- Простой считается по инцидентам, а не по телеметрии: незафиксированный отказ
  в расчёт не попадёт.
- Ставка и лимит неустойки одинаковы для всех договоров в генераторе; в реальности
  они различаются — поля уже вынесены в `dim_contract`.
- Норматив реакции задан долей от норматива решения (25 %), в договоре он может быть
  отдельной строкой.
