# Аналитика заявок первой линии

Разбор потока обращений в поддержку терминального парка: структура причин, соблюдение
SLA по приоритетам, нагрузка операторов и устройства, по которым обращаются повторно.
Смысл — превратить поток заявок в управленческие решения: где рвётся срок, что чинить
профилактически, каких обращений становится больше.

Данные синтетические, истинная категория каждой заявки известна генератору — поэтому
качество правил категоризации измеряется, а не заявляется.

## Результат на данных по умолчанию

2 500 заявок за 60 дней, 140 устройств, 8 операторов:

| Показатель | Значение |
| --- | ---: |
| Заявок / открытых | 2 500 / 76 |
| Критичных P1 | 250 |
| Соблюдение SLA | 86,0 % |
| Средняя реакция | 3,25 ч |
| Среднее решение | 30,9 ч |
| Повторных обращений | 247 (9,9 %) |
| Точность категоризации правилами | 86,0 % |

Структура обращений: оплата и проведение операций — 19,8 %, оборудование — 15,4 %,
связь с процессингом — 15,2 %, ПО — 12,2 %, консультации — 10,7 %, наличные — 10,2 %,
доступ на объект — 6,6 %. Не распознано правилами — 11,5 % (очередь на доработку).

## Как работает

```
текст темы → правила по ключевым словам (7 категорий + OTHER)
сроки      → нормативы P1/P2/P3: 2/8, 4/24, 8/72 ч, просрочки реакции и решения отдельно
повторы    → то же устройство + та же категория в течение 7 дней после закрытия
витрины    → категории, SLA, операторы, каналы, партнёры, недельная динамика, повторы
```

Порядок правил и обоснование порогов — `docs/methodology.md`. Ключевое: «как оформить
возврат по чеку» — это консультация, а не проблема принтера, хотя слово «чек» есть в обоих.

## Быстрый старт

Python 3.10+ (проверено на 3.14), внешних пакетов нет.

```powershell
python src/generate_tickets.py
python src/analyze.py
python src/report.py
```

Результат: витрины в `data/processed/`, отчёты `reports/dashboard.html` и `reports/summary.md`.

Тесты:

```powershell
python -m unittest discover -s tests -v
```

## Структура

```
src/generate_tickets.py  заявки: тексты, приоритеты, сроки, каналы, истинные категории
src/analyze.py           категоризация, SLA, повторные обращения, витрины
src/report.py            HTML-дашборд и markdown-резюме
tests/test_tickets.py    9 тестов: правила, SLA, повторы, целостность витрин

```

## Принятые решения

- **Правила вместо модели.** Семь категорий и сотни обращений в месяц: правило можно
  объяснить оператору и поправить за минуту. Модель дала бы +5 п.п. точности и ноль
  объяснимости; на этом объёме это плохой размен.
- **Порядок правил — часть логики.** «Чек» в вопросе про возврат не должен уводить
  заявку в принтеры, поэтому консультации проверяются раньше оборудования.
- **Повтор — это та же причина, а не любое обращение.** Иначе касса в проходном месте
  с высокой нагрузкой всегда выглядит «проблемной».
- **Просрочка реакции и просрочка решения — разные метрики.** Они указывают на разные
  узкие места: приём заявки или исполнение.
- **Открытые заявки не входят в среднее время решения.** Иначе MTTR зависит от даты
  запуска отчёта.
- **`OTHER` не прячется.** 11,5 % нераспознанных — это список формулировок, которыми
  надо дополнить правила, а не сбой, который надо замазать.

## Ограничения

- Правила не видят контекст предыдущих обращений по устройству.
- Категории пересекаются по смыслу: «нет связи» и «не проходит оплата» часто одна причина.
- Данные синтетические: структура категорий задана генератором, а не реальным потоком.
