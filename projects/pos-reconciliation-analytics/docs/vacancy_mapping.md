# Маппинг на требования вакансии

Вакансия: аналитик данных в команде поддержки терминального оборудования
(обработка больших объёмов данных, анализ показателей, сверка систем, отчётность).

## Задачи из вакансии → артефакты проекта

| Задача из описания | Где в проекте | Что показывает |
| --- | --- | --- |
| Обработка и подготовка больших объёмов данных по терминальному оборудованию и устройствам самообслуживания | `src/generate_data.py`, `src/build_db.py`, `sql/01_schema.sql`, `sql/02_staging_clean.sql` | Поток 186 тыс. операций по 80 устройствам, очистка, дедупликация, приведение типов; масштабирование до 4 млн строк одной командой |
| Анализ ключевых показателей | `sql/05_marts.sql`, `reports/dashboard.html`, `powerbi/measures.dax` | Доступность парка, MTTR, нарушения SLA, доля одобренных, средний чек, оборот, доля расхождений |
| Сверка, интеграции и выводы о расхождениях между системами | `sql/03_reconciliation.sql`, `sql/04_control_totals.sql`, `src/report.py` | Построчная сверка по RRN, шесть классов расхождений с приоритетом, контрольные суммы «партнёр × день», сумма под риском |
| Подготовка отчётов, презентаций и заключений | `src/report.py`, `reports/summary.md`, `docs/methodology.md` | Готовый HTML-дашборд, markdown-резюме с выводами, описанная методика расчётов |
| Защита данных перед заказчиком | `src/anonymize.py`, `powerbi/model.md` | Маскирование PAN (BIN + последние 4), серийников, контактов; псевдонимизация RRN с сохранением соединений |
| Переговоры с партнёрами в рамках компетенций | `reports/summary.md`, разрез `mart_partner_daily` | Разрез по партнёрам: оборот, расхождения, сумма под риском — основа для разговора с конкретным партнёром |

## Требования → подтверждение

| Требование | Чем подтверждается |
| --- | --- |
| Высшее образование | Вне проекта |
| Опыт с банковским терминальным оборудованием (УС/POS) | Доменная модель: POS, киоски самообслуживания, банкоматы; типы операций `PURCHASE`, `PAYMENT`, `CASHOUT`, `REFUND`; статусы `APPROVED`/`DECLINED`/`REVERSED`; инциденты по кодам ошибок терминалов |
| Продвинутый Excel, MS Office | Выгрузки в CSV с `;` и UTF-8 BOM — открываются в русском Excel без «кракозябр»; суммы в копейках, чтобы не терять точность при пересчёте; Power Query-запросы в `powerquery/` |
| Работа с большим объёмом данных | 186 тыс. операций за 30 дней в базовом прогоне, линейное масштабирование до миллионов строк; SQL-агрегации вместо ручной обработки |
| Детальный анализ, структурированность | Приоритет классов расхождений, инварианты контрольных сумм, тесты на точное совпадение с эталоном |
| Power Query | `powerquery/10_devices.m` … `45_duplicates.m`: подключение CSV, типизация, дедупликация, полная сверка без БД |
| SQL | `sql/01…05`: оконные функции, CTE, полное внешнее соединение, схлопывание пересекающихся интервалов |
| Power BI | `powerbi/measures.dax` (25 мер) и `powerbi/model.md` (схема «звезда», правила моделирования) |

## Что сказать на собеседовании

1. «Сверку я строю по RRN с приоритетом классов: одна операция — одна строка отчёта,
   иначе счётчики не сходятся с контрольными суммами».
2. «Деньги храню в копейках целым числом — на миллионах операций плавающая точка
   даёт расхождение в копейку, и его потом ищут вручную».
3. «Доступность считаю с схлопыванием пересекающихся инцидентов, иначе она уходит в минус».
4. «Качество сверки проверяю эталоном: генератор знает, какие RRN испорчены,
   и тест требует точного совпадения по каждому классу».
5. «Перед передачей заказчику данные обезличиваю, но RRN псевдонимизирую так,
   чтобы соединения в отчёте не ломались».
