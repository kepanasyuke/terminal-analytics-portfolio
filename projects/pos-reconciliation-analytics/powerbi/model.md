# Модель Power BI

## Схема

```
date_dim ──1:*── mart_partner_daily ──*:1── dim_partner (partner_id)
                        │
                        └──*:1── mart_recon_summary (по exception_type — только для срезов)

dim_device ──1:*── mart_device_sla ──*:1── dim_partner
     └──1:*── mart_error_codes (агрегат, связь не нужна — используется как отдельная таблица)
```

Факты и измерения:

| Таблица | Тип | Гранулярность | Ключи |
| --- | --- | --- | --- |
| `mart_partner_daily` | факт | партнёр × день | `partner_id`, `txn_date` |
| `mart_device_sla` | факт | устройство | `device_id` |
| `mart_recon_summary` | факт | класс расхождения | `exception_type`, `severity` |
| `mart_error_codes` | факт | код ошибки | `error_code` |
| `mart_kpi` | карточки | одна строка | — |
| `dim_device` | измерение | устройство | `device_id` |
| `date_dim` | измерение | день | `date` |

## Правила моделирования

1. **Деньги только в копейках.** В витринах суммы — `INTEGER` в копейках, в рубли
   переводит одна мера-обёртка (`Оборот, ₽ = SUM(...)/100`). Так исключены расхождения
   в копейку между отчётом, Excel и выгрузкой в бухгалтерию.
2. **Никаких вычисляемых связей по названиям.** Все соединения — по суррогатным ключам
   (`partner_id`, `device_id`), названия партнёров и моделей — атрибуты измерений.
3. **Расхождение — это факт, а не метка строки.** `mart_recon_summary` позволяет строить
   срезы «класс × партнёр × день» без повторного чтения построчных исключений.
4. **Показатели доступности не суммируются.** Доступность всегда `AVERAGE` по устройствам;
   сумма процентов по партнёрам даёт бессмысленные числа.
5. **Инкрементальное обновление.** `mart_partner_daily` партиционируется по `txn_date`,
   окно хранения — 24 месяца, обновление только последних 7 дней.
6. **Безопасность.** В модель попадают только обезличенные выгрузки (`src/anonymize.py`):
   PAN в виде `BIN + ****** + last4`, серийные номера замаскированы, RRN при необходимости
   псевдонимизируются с сохранением соединений.

## Что показывает отчёт

Страница 1 — «Сверка»: KPI (расхождения, сумма под риском, доля расхождений), матрица
«класс расхождения × партнёр», тренд расхождений по дням.

Страница 2 — «Доступность»: доступность парка по типам устройств, топ-20 устройств
с доступностью ниже 97%, MTTR и нарушения SLA по кодам ошибок.

Страница 3 — «Операции»: оборот и одобряемость по партнёрам и дням, средний чек,
сезонность по дням недели.

## Проверка корректности

Меры сверяются с эталоном из пайплайна:

```
Операций (DAX) = mart_kpi.txns_cnt
Сумма под риском, ₽ (DAX) = mart_kpi.amount_at_risk_kop / 100
```

Расхождение больше нуля означает, что в модель попали строки вне периода или
не подтянулось измерение — проверяется визуалом «Операций по датам» против `control_totals`.
