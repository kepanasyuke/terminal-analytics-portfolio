# Сверка терминальной сети: расхождения, доступность, отчётность

Портфельный проект под задачи аналитика, который работает с данными терминального
оборудования (POS, киоски самообслуживания, банкоматы): обработка больших выгрузок,
сверка двух систем, расчёты ключевых показателей и отчёт для заказчика.

Данные синтетические: генератор создаёт правдоподобный парк устройств, поток операций
и поток инцидентов, а затем намеренно вносит известный набор расхождений между
журналом терминалов и процессингом — чтобы качество сверки можно было измерить,
а не «на глазок» оценить.

## Что умеет пайплайн

1. **Генерирует данные** двух независимых источников: журнал терминалов (TMS) и
   проводки процессинга, плюс справочники устройств, торговых точек и инцидентов.
2. **Загружает их в SQLite** и приводит к схеме «звезда» (`sql/01_schema.sql`).
3. **Сверяет системы построчно по RRN** и классифицирует расхождения по шести классам
   с приоритетом, чтобы одна операция не попала в отчёт дважды.
4. **Считает контрольные суммы** «партнёр × день» — проверка полноты выгрузки.
5. **Строит витрины**: доступность и SLA по устройствам, KPI партнёров по дням,
   разрез по кодам ошибок, сводку расхождений.
6. **Собирает отчёт**: самодостаточный HTML-дашборд и markdown-резюме, плюс CSV
   для Excel и Power BI.
7. **Обезличивает выгрузку** перед передачей заказчику: PAN, серийники, телефоны,
   e-mail, при необходимости — псевдонимизация RRN с сохранением соединений.

## Быстрый старт

Требуется Python 3.10+ (проверено на 3.14) и SQLite 3.39+ (нужен `FULL OUTER JOIN`;
в Python 3.14 идёт 3.50). Внешних пакетов нет — только стандартная библиотека.

```powershell
python src/generate_data.py --devices 80 --days 30
python src/build_db.py
python src/run_sql.py
python src/report.py
```

Время на машине разработки: генерация 12 с, загрузка 6 с, SQL 12 с, отчёт 0,5 с.

Тесты:

```powershell
python -m unittest discover -s tests -v
```

Обезличивание выгрузки перед отправкой заказчику:

```powershell
python src/anonymize.py --in reports/recon_exceptions.csv `
                        --out reports/recon_exceptions_masked.csv --tokenize-ids
```

## Ключевые решения

- **Деньги в копейках, `INTEGER`.** Ни одной операции с плавающей точкой на суммах:
  расхождение в копейку между отчётом, Excel и бухгалтерией недопустимо.
- **Приоритет классов расхождений.** Одна операция — одна строка отчёта. Иначе
  «пропажа + расхождение суммы» раздувает счётчики и ломает сверку с контрольными суммами.
- **Полное внешнее соединение без `FULL OUTER JOIN` в основном запросе.**
  `LEFT JOIN` + анти-выборка переносится на PostgreSQL и MS SQL без переписывания.
- **Пересекающиеся инциденты схлопываются** перед расчётом простоя: иначе доступность
  уходит в минус, когда два инцидента наложились по времени.
- **Дефекты в данных известны заранее.** Тест сверяет найденные классы расхождений
  с эталоном из `_injected_defects.json` — сверка проверяется числом, а не глазами.

## Масштабирование

Пайплайн рассчитан на объёмы, которые не влезают в Excel:

```powershell
python src/generate_data.py --devices 400 --days 90
```

Это порядка 4 млн операций; узкое место — загрузка CSV в SQLite по строкам, её
меняют на `duckdb.read_csv` или `COPY` в PostgreSQL. Дальше всё считается SQL-ом,
поэтому переход на PostgreSQL — это замена трёх скриптов, а не переписывание логики.
Витрины остаются теми же, Power BI и Excel продолжают читать те же CSV.

## Ограничения

- Данные синтетические; выводы из таблиц выше — свойства генератора, а не рынка.
- Расхождения классифицируются по одному приоритетному признаку; вторичные
  (например, одновременно другой статус и другое время) в отчёт не выводятся.
- Доступность считается по инцидентам, а не по телеметрии: если система мониторинга
  не зафиксировала простой, он не попадёт в расчёт.

## Графика в дашборде

Отчёт рисует данные сам: линейный график расхождений по дням, донат по классам и
анимированные счётчики KPI. Всё на инлайновом SVG без библиотек и без сети, файл
открывается двойным щелчком. Анимация отключается системной настройкой
`prefers-reduced-motion`. Графики строятся из тех же CSV-витрин, что и таблицы,
поэтому не расходятся с цифрами.
